# 安装与管理插件

插件可以给主面板增加页面、快捷操作或后台能力。只安装你了解来源的插件。

## 导入插件

Tempo 支持插件目录、`.zip` 包，以及 Git 插件仓库。从目录或 ZIP 导入前，包的根目录中必须有 `manifest.json`。

自己维护一组插件时，在 **设置 → 插件管理 → 插件仓库** 点 **从模板创建**，Tempo 会把官方模板写到本机。推送到 Git 后，再用 **添加源** 添加这个远程地址。Tempo 只安装仓库里已经提交的 `dist/`，不会在你的电脑上构建插件。

1. 打开 **设置 → 插件管理**。
2. 选择 **导入目录** 或 **导入 ZIP**。
3. 检查插件名称、版本和声明的权限。
4. 启用插件。
5. 回到主面板，搜索插件名称。

导入只是把插件加入 Tempo。插件是否立即可用，还取决于它有没有后台脚本。

## 信任与 Deno 运行时

插件分为两类：

| 插件内容 | 你需要做什么 |
| --- | --- |
| 只有页面 | 导入并启用即可 |
| 包含后台脚本 | 安装插件 Deno 运行时，再明确点“信任” |

后台脚本默认在受限 Deno 进程中运行，插件 UI 在隔离视图中运行。Manifest v2 的八项敏感权限都可独立开关：全局文件读取、全局文件写入、网络、环境变量、系统信息、子进程、动态库和远程导入。网络权限同时控制 Runtime 与托管 UI。Tempo Host API 不需要单独授权，`tempo.files` 始终只访问该插件的私有数据目录。信任和升级前会显示权限清单；这不是 OS 级沙箱，仍需选择可信来源。

旧 Manifest v1 插件必须升级到 v2 并重新打包、导入和信任，不会回退到 Node。插件数据目录保持不变，停用不会删除私有存储。

信任插件前，至少确认：

- 插件来自你认可的作者或仓库。
- 插件声明的每一项全局权限都符合它的用途。
- 更新后的版本没有突然增加不相关的权限。

## 启用、停用与卸载

- **停用**：暂时移除插件入口并停止后台。当前版本还会清空该插件的 Host KV 与页面 Session；Runtime 文件数据目录会保留。
- **卸载**：移除插件包。操作前留意界面是否提示保留或删除数据。
- **更新**：导入同一插件的新版本后，按插件列表中的提示切换版本。

插件出现异常时，先停用再重新启用。带后台脚本的插件还可以检查运行时状态和日志。

## 插件配置与 AI 工具

有配置项的插件会在插件详情中显示“插件配置”。这些设置由 Tempo 保存，插件只能读取自己的数据。

插件声明的 MCP 工具默认不会暴露给 AI 客户端。只有你在插件详情中打开 MCP 暴露，并启用具体工具后，外部客户端才能调用。
